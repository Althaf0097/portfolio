## 2025-07-29 - Cache InteractiveCard elements dimensions to prevent layout thrashing
**Learning:** High-frequency mouse tracking logic calling `getBoundingClientRect()` inside the `onMouseMove` event handler triggers layout thrashing, causing the browser to repeatedly recalculate styles and layout. In Three.js and heavy R3F/GSAP apps, this causes severe main-thread lags. Additionally, instantiating `THREE.CanvasTexture` on every single render inside the render cycle creates a massive garbage collection bottleneck and memory leak.
**Action:** Always cache dimensions in a `useRef` on `onMouseEnter`, correct viewport coordinates with scroll offsets (`window.scrollX`/`window.scrollY`) to allow page-relative mouse coordinates (`e.pageX`/`e.pageY`) to work perfectly without calling the API inside the mousemove loop. Also, always wrap canvas-texture creation and procedurally generated positions inside `useMemo` hooks.
