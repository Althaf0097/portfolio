## 2025-02-18 - High-Frequency Layout Recalculation & DOM Mutation Optimization
**Learning:** During hover effects, continuously calling `getBoundingClientRect()` inside a `mousemove` listener triggers forced synchronous layouts (layout thrashing) because the browser has to recalculate layout properties before completing the script. Moreover, continuously updating inline CSS radial gradients on every single pixel movement causes heavy paint operations on the CPU, dropping frame rates.
**Action:** Cache the element's layout geometry inside a `useRef` on mouse entry to make mouse tracking completely read-only on high-frequency movements. Offload visual spotlight rendering to a static overlay element, and animate its position using a highly performant 3D hardware-accelerated transform via `gsap.quickTo` (`transform: translate3d(...)`) to delegate rendering computations entirely to the GPU and eliminate layout thrashing.
